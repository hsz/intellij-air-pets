`SessionSummary.id` is explicitly deprecated: its message says the legacy row ID mixes workspace, runtime route, and external/local session ID, and recommends `workspaceId` and `localSessionIdentity`. The adapter therefore derives pet IDs only from `LocalSessionIdentity`, using a length-prefixed directory plus local session value to avoid delimiter collisions. Backend session assignment, provider routing, title, and activity do not change a pet's ID.

Bytecode for `SessionSummary.isWaitingChainedSession` checks nonempty `waitingOnPredecessors` **or** `aggregateExclusion == WAITING_CHAINED_SESSION`; it is not inferred from the title or a backend session ID.

`SessionWorkspace` is an abstract class in the pinned artifact, but other AIR builds expose it as an interface. Calls compiled against its class getters then fail with `IncompatibleClassChangeError`. The adapter reads getters on concrete `ProjectWorkspace` and `WorktreeWorkspace` objects and projects them into a private workspace value before combining them, avoiding that shared-type ABI dependency without reflection. `AirSessionWorkspaceCompatibilityTest` recreates the interface shape in an isolated class loader and reruns the discovery tests; it reproduced the reported exception before this change. This covers this specific ABI change, not arbitrary AIR API changes.

## Projection rules

- Compare the current `Project.basePath` with workspace `PathRef.value` using IntelliJ `FileUtil.pathsEqual`, never substring/prefix matching. Missing/blank paths select nothing.
- A matching project root includes that root and its worktrees. If only a worktree matches, include only that worktree, not its root or siblings. No unrelated project's sessions or folders enter the projection.
- Omit archived summaries. Deduplicate by stable local identity. Match done-folder members by the **entire** local identity, including the directory.
- Live `PROCESSING`, `NEEDS_INPUT`, and `REVIEWING` map to `WORKING`, `WAITING`, and `REVIEW` before considering stale errors or completion hints. Chained waiting maps to `WAITING`; otherwise stopped errors map to `ERROR`. A `NEEDS_ATTENTION` occurrence maps to `WAITING` before completion. `UNREAD`, a `COMPLETED` occurrence, or membership in a `DONE` folder maps to `DONE`; remaining `READY`/`DRAFT` sessions map to `RESTING`.
- The adapter maps `SessionSummary.cost` to `SessionCost` only when the amount is present, nonnegative, and the kind is `EXACT` or `ESTIMATED`; it preserves the `BigDecimal` amount and sets `estimated` for the latter. A null cost, null amount, `UNAVAILABLE`, or negative amount maps to `null`, never to zero. Zero is a valid amount. The existing `SessionDiscoveryState.sessions` flow delivers cost changes with ordinary session snapshot updates; no polling is used.
- Every discovery emission replaces its project's navigation index, even if the emitted pets compare equal. Removed/archived sessions cannot be opened from an old pet ID. `open` checks project ownership/current base path and uses the latest summary's agent, local session ID value, and optional backend session ID. Missing IDs or unavailable navigation return `false`.
- Collection is cold and does not create a scope, dispatcher, retry loop, or background job. The owning project service manages background collection, cancellation, retries, and calls `open` on the EDT. Discovery/navigation exceptions are not silently swallowed.

## Marking a session done

AIR's per-session Done action archives the session; only folder completion changes `SessionFolderStatus`. The heart control uses the same application-level archive service as the individual Done action, passing the exact indexed `LocalSessionIdentity` and `TREE_ROW_OVERLAY`. It never completes a folder, deletes a session, or opens it as a side effect.

`markDone` validates the project, current base path, latest indexed summary, and current completed state before dispatching. Its injectable archive boundary permits tests without starting an agent or altering real sessions. The project service suppresses simultaneous duplicate clicks, keeps demo completion entirely local, and reports unavailable/failed completion through the status-bar menu and tooltip.

The archive call is asynchronous. The adapter returns success only after `allRequestedArchived`, not merely after dispatch. AIR may omit its callback on an RPC error, so the wait is cancellable and bounded to 30 seconds; duplicate and late callbacks are ignored. A timeout means completion could not be confirmed, not that AIR cannot subsequently archive the session. Pets are removed only by AIR discovery's archived/removed update, never optimistically on a live click.

## Existing-session Quick Chat

Quick Chat uses a new native content instance rather than obtaining or reparenting AIR's mounted editor/toolwindow. `AirSessionSource.quickChatTarget` revalidates the same scoped catalog index as navigation. `nativeChatTarget` uses `summary.workspaceId` and the local identity's exact directory, including worktrees. AIR's view SPI still needs routing from the deprecated `summary.id`: `agentId`, `launchTargetId`, and `providerSessionId` produce an `AgentSessionAddress`; `address.sessionIdentity` is the thread identity (for example `junie:provider-session`). The context's `threadId` must also be `summary.id.providerSessionId`, AIR's local/runtime thread key. `summary.agentSessionId` is the external agent/ACP session ID, not that key. Stable pet IDs remain entirely local-identity based.

Backend evidence: `intellij.air.backend.session.view.gui.jar!/com/intellij/air/backend/session/view/gui/BackendThreadGuiApi.class` passes `ThreadGuiRef.threadId` unchanged into its session-log key. `BackendThreadGuiApiKt.threadGuiSessionRef` creates a `SessionRef` from the exact project directory and this local ID; there is no external-to-local ID translation. Supplying `agentSessionId` therefore reads a different/missing log, producing an empty Draft with `RUNTIME_NOT_ATTACHED`. AIR's normal tool-window opener likewise passes `summary.id.providerSessionId` as its thread ID.

Only the native interaction surface is embedded. A missing surface defaults to native for nonterminal launch targets on both supported API shapes; terminal launch targets with a missing surface and explicitly non-native or invalid surfaces produce a fallback with **Open in AIR**, not a direct-send endpoint. The launch profile is nullable and deferred-start state is always null: opening a pet must not create or resume execution as a side effect. AIR retains responsibility for prompt submission, permissions, questions, context, and message rendering. Subagent navigation and the full session menu remain in full AIR; the popup always provides that explicit navigation action.

The installed IJ 271 AIR artifacts remove `SessionSummary.getInteractionSurfaceId()` and expose the nullable, inline-value-class getter `getEffectiveInteractionSurfaceId-Q0pYR-A()` instead. Bytecode shows that this getter passes null, agent ID, and launch target to `effectiveInteractionSurfaceIdOrNull`: it returns terminal for `terminalAgentLaunchTargetId(agentId)` and null otherwise. Null therefore does not mean native chat is unavailable; rejecting it made ordinary IJ 271 sessions always show the unavailable fallback. Quick Chat applies the native default to nonterminal routes while preserving the exact session address and rejecting terminal/invalid surfaces. They also replace the flattened `AgentThreadViewContentContext` constructor with `(AgentThreadViewContentIdentity, AgentPromptLaunchProfile?, String?)` and move the session fields onto `identity`. Quick Chat uses narrowly matched reflective getter/constructor lookups for these two API boundaries, while reading identity fields through the typed API shared by both builds. A missing getter still declines embedding. The content file exposes a `StateFlow` address, compatible with the legacy `Flow` and newer `StateFlow` signatures. `AirQuickChatCompatibilityTest` reproduces the removed getter and identity-only context in an isolated loader; it failed with the exact reported `NoSuchMethodError` before the first fix, and with the unavailable fallback for a null modern surface before the follow-up fix. Its effective-surface fixture also models terminal launch-target inference. This covers these known API shapes, not arbitrary future AIR changes.

Content creation, installation, selection, and disposal occur on the EDT. The host's showing promise resolves only when its component is really showing. Each cached native view has its own child coroutine scope and disposable, and only one popup is active per project. Popup closure detaches the component and invokes `deselectNotify`; reopening reuses it and invokes `selectNotify`. Confirmed session removal/archiving and project disposal cancel its scope and dispose all native resources. Temporarily unavailable discovery dismisses the popup but does not evict ready native views.

Draft retention deliberately uses native-view lifetime rather than an invented save API. In this pinned build, `ThreadGuiThreadScreen` owns a private `ThreadGuiComposerDraftManager`; its parent-disposal callback unmounts the screen and cancels its scope without calling `persist()`. The observed `persist()` call is a message-edit callback, not general close-time autosave. `AgentSessionPromptDrafts.saveDraft` is typed but requires live text/restorable context that the content SPI does not expose. There is no typed flush method. Therefore cached composers preserve text/attachments while the project remains open, but the plugin makes no persistence guarantee across project close/restart. Native draft keys use workspace path plus session identity; a full-AIR composer and popup composer are not live-merged and should not be edited concurrently.

## Actual limitations

- These catalog, identity, navigation, archive, and native-content APIs are marked `ApiStatus.Internal`. They are pinned implementation APIs, not a supported cross-version AIR SDK; inspect and retest them when upgrading AIR or IntelliJ. IDE inspections flag this internal API usage, including Marketplace publication restrictions; this remains a local prototype, not a Marketplace-ready public API integration.
- Frontend `READY` does **not** distinguish every backend paused, idle, interrupted, or waiting substate. The adapter reports the honest coarser `RESTING` state (detail: “ready or paused”); it does not invent backend precision or scrape UI text/logs.
- `UNREAD` and completion occurrences are presentation/completion signals, not a guarantee that a task's desired outcome succeeded. `DONE` folders represent catalog organization. Current live activity takes precedence over these potentially older signals.
- Navigation returns `Unit`, so adapter success means the AIR navigation service was available and accepted the call, not proof that a particular editor became visible.
- AIR does not expose accumulated elapsed or working duration on the session catalog summary. Its session-tree time label is relative recency: `ThreadTreeThreadPresentationKt` passes `SessionSummary.displayOrderAtMs` into `ThreadTreeRelativeTimeLabels.label(timestamp, now)`, and `displayOrderAtMs` is derived from `providerUpdatedAtMs`/`lastUserPromptAtMs`. The “show time” setting toggles this presentation; it is not a duration API. The pet UI therefore uses a locally observed **working-time** counter, accumulated only over observed `WORKING` intervals, not a historical AIR session total. Those local timers reset when the project closes; intervals outside observation are not included.
